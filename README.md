# 思潜狼人杀 · 网页法官工具

纯前端、无需 npm 或后端，可直接部署到 GitHub Pages。法官仍在线下发身份牌；网页负责身份登记、夜间流程、语音口令、夜间结算、警徽、白天事件与发言顺序。

## 本次修复

这版针对上一版“乱码、页面打开卡住、无法运行”做了完整重建：

- 重写 `app.js`，移除被错误编码污染后膨胀到数 MB 的损坏脚本；现在主脚本恢复到正常体积。
- 所有源码统一为 UTF-8 / LF，并新增 `.editorconfig`、`.gitattributes`，降低再次出现编码污染的概率。
- `index.html` 为静态资源加入版本参数，上传 GitHub Pages 后可以避开旧版损坏脚本的浏览器缓存。
- 旧房间中的历史板型 ID `wolfGuard12`、`nightmareGuard12`、`wolfDream12` 会自动迁移到新 ID，不需要手动重建房间。
- 加入错误兜底：主脚本若真的启动失败，页面会显示错误提示，而不是一直停在空白页。
- 增加 `tests/smoke-core.cjs` 做核心规则回归检查，并加入 `tests/smoke-speech.cjs` 验证播报会在点击调用栈中同步触发。

## fix5 上警与夜间身份登记调整

- 第一天下警上登记完成后，点击“确认警上名单并播报”，固定播报：`本局游戏上警玩家为X号，Y号……。`

## fix4 流程与播报调整

### 梦魇局技能状态

在“12 人梦魇守卫”中，受恐惧影响的身份现在会在使用技能前先确认状态：

- 守卫、狼人阵营、女巫、预言家的“技能状态”口令紧跟在“XXX 请睁眼”之后。
- 猎人的“你的开枪状态为”本身就是状态提示，同样紧跟睁眼口令。
- 即使神职被梦魇恐惧，也会完整走完原本的主持口令，避免通过夜间播报长短泄露恐惧目标；但被恐惧神职的技能仍然无效。
- 弱梦魇恐惧到狼人时，狼人仍可确认同伴和商量战术，但本夜不再录入狼刀。
- 女巫口播统一为“今夜死亡玩家为。”；即使女巫被恐惧，仍会显示死亡玩家信息框并完成正常口播，但不会开放有效用药操作。

### 第一天警长竞选与死讯

第一天严格按以下顺序辅助法官：

1. 先播报“准备天亮，所有玩家闭眼举手上警，请警下玩家放倒号码牌。”
2. 播报完成后才开放警上玩家登记。
3. 系统从全桌 1～12/13 号中随机并固定一个点数；奇数按顺序、偶数按逆序，再沿该方向找到第一位警上玩家开始发言。
4. 播报时不再解释“奇数/偶数”，只直接说“顺序”或“逆序”。
5. 先记录警长结果，再公布昨夜死讯。
6. 因为死讯是在警长竞选之后公布，第一天允许昨夜已经死亡的警上玩家先当选警长；死讯公布后会自动显示“警长已死亡”，要求移交或撕毁警徽。

### 死讯固定句式

夜间死亡号码会先按从小到大排序，再按人数使用固定播报：

- 0 人：“昨夜平安夜。”
- 1 人：“昨夜，X号玩家单死。”
- 2 人：“昨夜双死，死亡顺序不分先后，X号，Y号。”
- 3 人及以上：“昨夜多死，死亡顺序不分先后，X号，Y号，Z号……”

### 白天发言顺序

无警长时仍按随机号码决定方向：

- 奇数号码 → 顺序。
- 偶数号码 → 逆序。
- 随机到已出局玩家时，按既定方向顺延到第一位存活玩家。
- 实际播报只给最终方向，不读“奇数/偶数”判断过程。

有存活警长时不再让法官任意选择起点和方向：

- **昨夜单死**：警长只选择“死左发言”或“死右发言”。
- **昨夜平安夜、双死或更多死亡**：警长只选择“警左发言”或“警右发言”。
- 系统自动跳过已出局玩家，警长固定最后发言归票，并播报：“X号玩家请发言，Y号玩家做发言准备。”

### 狼人阶段固定口令

固定口令保留：

> 狼人阵营确认同伴，商量战术，决定击杀目标。

有狼王、狼美人、梦魇时仍会提供对应“请举手”口令。

### 强梦魇 / 弱梦魇

创建“12 人梦魇守卫”时可以选择：

- **强梦魇**：恐惧狼人时无事发生，狼队仍可正常带刀。
- **弱梦魇**：恐惧狼人时，本夜狼队不能带刀，因此女巫没有有效狼刀目标可救。
- 恐惧守卫、女巫、猎人、预言家等神职时，该身份本夜技能无效；法官界面显示状态，不语音泄露结果。
- 当前规则中梦魇不能连续两夜恐惧同一人。

### 混血儿查验

**混血儿始终被预言家查验为好人。**

混血儿的阵营逻辑仍可以随榜样变化，但这不会改变预言家的查验结果。

## 语音播报

> **fix3 语音修复（fix4 继续保留）：** 上一修复版为了等待 IndexedDB 真人录音并规避部分 Android 连播问题，把 `speechSynthesis.speak()` / `Audio.play()` 放到了异步任务中。iOS Safari 和部分移动浏览器会因此丢失“用户主动点击”的音频权限，表现为按钮有反应但完全没声音。fix3 已改为在点击事件同步调用栈内立即启动系统 TTS 或真人录音，不再在播报前 `await` 或 `setTimeout`。同时避免在语音空闲时无意义地 `cancel()`，减少下一句被吞掉的情况。

`SpeechSynthesis` 本身取决于手机/电脑系统提供的音色，所以网页无法保证所有设备上的系统 TTS 都像真人。本版做了三层改进：

1. 自动优先选择设备里名称带 Natural / Neural / Enhanced / Premium 等标识的中文高质量音色。
2. 默认使用偏慢、偏低音调的“自然播报”参数，并可在“音色 / 真人录音”中调整。
3. **固定口令可直接在网页里录真人语音，也可以上传 MP3 / WAV / M4A / AAC / OGG / WebM。** 播报时真人录音优先，未录制的动态口令才回退到系统语音。

真人录音存放在当前浏览器 IndexedDB，不上传服务器，也不会随房间 JSON 导出。网页内录音需要 HTTPS；GitHub Pages 默认满足这一条件。

## 主要规则结算

- 首夜禁止狼窝自刀；机械狼与普通狼互不相认，因此普通狼首夜仍可误刀机械狼。
- 女巫不能自救、不能同夜双药；首夜本人未吃刀且有有效刀口时，按思潜规则默认必须救。
- 守卫不能连续两夜守同一人；同守同救死亡；普通守卫不防毒。
- 白痴按强白痴处理：被白天放逐时翻牌免疫该次放逐，继续存活但失去投票权。
- 狼美人不能自爆、不能被狼队自刀；白天正常死亡时可按最近一次魅惑目标结算殉情，骑士决斗狼美人不触发殉情。
- 骑士只能决斗一次；决斗狼人时狼人出局，决斗好人时骑士出局。
- 摄梦人当前规则：梦游者免疫本夜狼刀和毒药；连续两夜摄梦同一人则该玩家死亡；摄梦人夜间死亡时本夜梦游者连带死亡。
- 机械狼支持首夜学习；学守卫可每天进行强化守护且不能连续守同一人，并可反弹女巫毒药；学女巫可获得一次可保留的毒药；学通灵师可查具体身份；学狼人并接刀后，在普通狼刀之外可于独立技能阶段发动一次可保留的破盾刀。

复杂特殊板型可能存在不同赛事或店规版本；正式开局前仍建议由法官确认本桌采用的具体规则。

## 房间与数据

- 多房间并存，每个房间独立保存。
- 浏览器 `localStorage` 保存房间状态。
- 最近 30 步可撤销。
- 房间支持 JSON 导入 / 导出。
- 多标签页通过 `storage` 事件同步刷新。
- 清除浏览器站点数据会删除房间和真人录音，因此重要对局建议先导出 JSON。
